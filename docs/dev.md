# Local dev and debugging

## Serve locally

From the project root:

```sh
python3 -m http.server 8080
# open http://localhost:8080/
```

Service workers and the install prompt both work on `localhost` (Chrome
treats it as a secure origin). Any static file server is fine; there's no
build step.

## Test under a subpath

To verify the app behaves at `/maxs-games/` (the GitHub Pages URL shape)
before deploying:

```sh
mkdir -p /tmp/subpath && cp -r . /tmp/subpath/maxs-games
cd /tmp/subpath && python3 -m http.server 8080
# open http://localhost:8080/maxs-games/
```

Everything should work identically. If something breaks here but works
at `/`, you've introduced an absolute path somewhere — find it and make
it relative.

## Service worker iteration

Iterating on cached assets is the painful part of PWA dev. Pick one
strategy and stick with it:

**Option A — DevTools "Update on reload"** (recommended while iterating):
1. Open DevTools → Application → Service Workers.
2. Tick **Update on reload** and **Bypass for network**.
3. Reload normally.

This bypasses the SW cache and forces a fresh SW install on every reload.

**Option B — Bump the cache version**: change `CACHE_VERSION` in `sw.js`
(`'v1'` → `'v2'`, etc.). On the next visit, the new SW installs, the
activate handler sweeps caches that don't match `maxs-games-v2`, and
clients re-fetch. This is what you should actually do when deploying a
real change.

**Option C — Nuke**: DevTools → Application → Storage → **Clear site
data**. Wipes caches, localStorage, the registered SW. Useful when the
state has gotten weird.

## Test offline

DevTools → Network → tick **Offline**. Reload. The hub and any precached
game should still load and run end-to-end.

If something 404s offline, it's missing from `PRECACHE` in `sw.js`. Add
it and bump `CACHE_VERSION`.

## Audio quirks

`AudioContext` won't produce sound until a user gesture. The first tap
inside a game unlocks it (see `audio.js` — `ensureCtx` resumes a
suspended context). If sounds aren't playing:
- Check the iframe got focus and received a tap.
- Check the device isn't muted (Android Chrome respects media-volume mute
  for Web Audio).

## Install on the tablet

1. Visit the deployed URL (or `localhost` over USB debugging) in Chrome.
2. Wait one beat for the SW to register.
3. Three-dot menu → **Add to Home screen** / **Install app**. Chrome
   will also surface a banner once it's eligible.
4. Launch from the home-screen icon. Verify it opens in standalone mode
   (no URL bar, theme color in the status bar).

PWA install eligibility is gated on:
- Manifest with `name`, 192 + 512 icons, `start_url`, `display: standalone`.
- A registered service worker that has at least one `fetch` handler that
  returned a valid response for the start_url.
- HTTPS, or `localhost`.

This project satisfies all of those — if Chrome refuses to install, look
at DevTools → Application → Manifest for the specific reason.

## Regenerate icons

Icons are generated by `tools/make-icons.mjs`. Edit the design (in that
file) and rerun:

```sh
node tools/make-icons.mjs
```

Outputs `icons/icon-192.png`, `icons/icon-512.png`,
`icons/icon-maskable-512.png`. The maskable variant keeps content within
the central 80% of the canvas (the safe zone for adaptive icons).

## Inspecting state

The kid's progress lives in `localStorage`:

```js
// from DevTools console
JSON.parse(localStorage.getItem('maxs-games:ball-sort'))
// → { level, difficulty, history: [...] }
```

To wipe a single game's state:

```js
localStorage.removeItem('maxs-games:ball-sort')
```

To wipe everything this project owns:

```js
Object.keys(localStorage)
  .filter(k => k.startsWith('maxs-games:'))
  .forEach(k => localStorage.removeItem(k))
```

## Debugging the iframe

The iframe is same-origin, so DevTools can debug into it normally:
DevTools → Sources → there's a separate frame in the file tree, breakpoints
work, console for that frame is selectable from the dropdown next to the
console filter input.

## Things that have bitten us before

- **Setting absolute paths.** Breaks subpath deployment. Always relative.
- **Forgetting to add a new file to `PRECACHE`.** Works online, breaks
  offline. Test offline before declaring a feature done.
- **Forgetting to bump `CACHE_VERSION` after a deploy.** Old SW serves
  old assets indefinitely. Always bump.
- **Adding a viewport meta with `user-scalable=no`.** Don't — it's an
  a11y issue. `touch-action: manipulation` already kills the 300ms tap
  delay.
